# 02. 반자동 실행 파이프라인 설계

## 1. 설계 원칙

1. **네이버는 글쓰기 API가 없다.** 발행은 브라우저 자동화로 에디터를 채우고, 발행 버튼은 사람이 누른다
2. **사람 게이트 2곳**: 주간 키워드 승인, 글별 발행 승인(사진 첨부 포함)
3. **속도보다 안전**: 하루 1편, 초안은 매일 새벽 생성, 발행 시각은 사람이 결정
4. **계정 정보는 코드에 없다**: 로그인 세션은 브라우저 프로필에 저장, API 키는 `.env`

## 2. 전체 흐름

```
[월요일 새벽] weekly_plan.py
  research  ─ 데이터랩 트렌드(이맘때) → 검색광고 API 월 검색량 → 검색 API 상위 노출 분석
  planner   ─ 유형 비율 반영해 주간 캘린더 5편 생성 → data/keywords/YYYY-WW.yaml (status: pending)
[월요일 아침] 사람: tracker.xlsx 📋 시트에서 status 를 approved/rejected 로 바꾸고 `export_excel.py --import` (10분)

[매일 새벽] daily_draft.py
  writer    ─ 승인 키워드 1개 → Claude 초안 (사진 슬롯 표시)
  reviewer  ─ 규칙 9항목 검사 → 미달 시 재생성(최대 2회) → Claude 품질 채점 → data/drafts/*.md (status: review)

[매일 아침] 사람: 초안 읽고 status: approved (10분) → 사진 5장 준비

[초안 후] course_assets.py --mountain 북한산  (고도 그래프·타임라인 표·레이더·카드)
[초안 후] attach_photos.py <draft> --keyword 북한산  (포토코리아 사진·출처 캡션)

[초안 후] transit_table.py <draft> --entry "북한산 우이동" --exit "북한산 구기동"  (첫차·막차 표)

[발행 전날] refresh_conditions.py <draft> --trailhead --mountain  (날씨·단풍·통제 블록)

[사람 실행] fill_editor.py <draft>
  publisher ─ Playwright로 네이버 에디터 열기 → 제목·본문·태그 채움 → 사진 슬롯 위치 강조 → 대기
  사람      ─ 사진 첨부, 최종 검토, **발행 클릭** (10분)
  publisher ─ 발행 URL 감지 → 초안 status: published, url 기록

[발행 직후] distributor (fill_editor가 이어서 실행)
  ─ X/Threads 요약 게시, 뉴스레터 큐 적재, 서치어드바이저 수집 요청 확인

[일요일 밤] weekly_report.py
  analytics ─ 블로그 통계 내보내기 파일 + 애드포스트 리포트 → data/reports/YYYY-WW.md
```

주간 사람 시간: 승인 10분 + (초안 검토 10분 + 사진·발행 10분) × 5 + 이웃 소통 40분 ≈ **2.5시간**

## 3. 모듈 설계

### research
- `datalab_trend.py`: 데이터랩 검색어 트렌드(API HUB) → 키워드별 연도별 피크 주차 → **피크 3주 전을 발행 주로** 캘린더에 배치 ("이맘때" 자동화)
- `trail_data.py`: 산림청 산정보(공공데이터포털 API) → 100대 명산 소개·볼거리. 등산로 선형은 `media/course_viz.py` 가 파일에서 읽는다
- `local_search.py`: API HUB 지역 검색 → 들머리 주변 식당 5곳 표
- `naver_ad_api.py`: 검색광고 API `keywordstool` 호출 → 월간 PC/모바일 검색량, 경쟁 정도. HMAC-SHA256 서명, 시드 5개 단위 호출, 주 단위 캐시(`data/keywords/cache/`), `< 10` 값은 0 처리 (구현 완료, `tests/` 에 단위 테스트)
- `naver_search_api.py`: NAVER API HUB 블로그 검색(`/search/v1/blog`, 구 개발자센터 키 폴백) → 상위 10개 결과의 개인 블로그 비율(기업 ID 패턴 제외), 네이버 블로그 비율, 최근 1년 글 비율, 상위 5개 제목(관점 잡기용). 주 단위 캐시 (구현 완료, 단위 테스트)
- 출력: `KeywordCandidate(keyword, volume, competition, personal_ratio, source)`

### media (사진)
- `media/photos.py` + `scripts/attach_photos.py`: 포토코리아 관광사진 API(공공누리 1유형)에서 산 이름으로 검색, 발행 월과 가까운 촬영월 우선 정렬, `[사진: 설명]` 슬롯을 이미지+출처 캡션으로 교체
- AI 보정(구도·색감)은 1유형 사진에만. 3유형(KorService2)은 원본 그대로

### design (디자인 토큰·아이콘)
- `config/design.yaml`: 색·글자 크기·간격·아이콘 비율. 카드·그래프가 모두 여기서 읽는다 → 한 곳만 바꾸면 전체 톤이 바뀐다
- `media/design.py`: 24×24 격자 벡터 라인 아이콘 17종(산·자·타이머·상승·불꽃·부츠·잎·버스·기차·핀·깃발·해·구름·경고·지도·가방·음식)을 PIL 로 직접 그림. 폰트·OS 무관, 4배 슈퍼샘플링
- `draw_row` 가 아이콘 높이를 글자 캡 높이에 맞추고 세로 중심을 정렬. `check_alignment` 테스트로 보장

### course_viz (코스 표현 자산)
- `media/course_viz.py` + `scripts/course_assets.py`: 산림청 등산로정보(전국등산로표준데이터, **파일** — GeoJSON/GPX 를 `data/trails/` 에 둠)에서 산·구간을 골라
  1. **고도 프로파일** PNG (거리 대비 고도, 지점 표시, 누적 상승) — 고도는 파일 값 또는 open-elevation 캐시
  2. **구간 타임라인 표** (출발 시각 기준 지점별 도착 시각·누적 거리·난이도, 정상 휴식·하산 포함)
  3. **난이도 레이더** PNG 육각형 (거리·고도차·경사·기술(구간 난이도 최댓값)은 데이터, 접근성·조망은 사람 입력. 여러 코스 겹치기 가능)
  4. **요약 카드** PNG 1080×1080 (대표 이미지·클립 표지용)
- 산출물은 `data/<exp>/assets/<산>/` 에 저장. 초안의 코스 표 아래에 이미지 마크다운을 넣는다
- SHP → GeoJSON: `ogr2ogr -f GeoJSON -t_srs EPSG:4326 out.geojson in.shp`

### transit (진입로·진출로 대중교통)
- `research/transit.py` + `scripts/transit_table.py`: 국토교통부 TAGO 버스 API — 들머리·날머리 좌표 반경 500m 정류소 → 경유 노선 → 노선별 **첫차·막차·배차(평일/토/일)** 표. 주 단위 캐시
- 지하철·시외버스 등 API 밖 정보는 `config/trailheads.yaml` 의 `transit_manual` 에 기록 (사람)
- 진출로 표에는 "막차 기준으로 하산 시각을 잡으라"는 안내를 붙인다. 타임라인 표와 함께 보면 출발 시각이 정해진다
- 서울 권역 들머리(좌표로 자동 판별)는 `research/seoul_bus.py` 가 서울시 정류소정보·노선정보 API(ws.bus.go.kr)로 간선·지선·마을버스 첫차·막차·배차를 가져온다. 같은 공공데이터포털 키

### tracker (엑셀 정리)
- `scripts/export_excel.py --exp hiker` → `data/<exp>/tracker.xlsx` 한 파일에 📋 키워드계획(status 색상) · ✍️ 초안(글자수·사진·요약·교통·현황·상품 체크) · 🖼️ 코스자산 · 📊 주간리포트 · ⚙️ 설정
- `--import` 로 엑셀에서 바꾼 status(approved/rejected)·관점 열을 YAML 에 되돌려 쓴다 → **주간 승인을 엑셀에서** 할 수 있다
- 매일 새벽 스크립트 끝에 export 를 붙여 항상 최신 상태를 유지

### conditions (발행 직전 현황 결합)
- `conditions.py` + `scripts/refresh_conditions.py`: 발행 전날 초안에 **'이번 주말 현황'** 블록을 넣는다
  - 날씨: 기상청 단기예보(공공데이터포털, 3일 이내) — 들머리 좌표(`config/trailheads.yaml`)를 격자로 변환해 06/09/12/15시 하늘·기온·강수확률
  - 단풍: `config/foliage.yaml` 연간 예측표(매년 9월 산림청·기상청 발표 후 갱신) → "절정 N일 전/시기/지남"
  - 통제: `config/closures.yaml` 수동 기록 + 국립공원공단 확인 링크. 공식 API 미확인이라 사람이 확인 후 기록
- fill_editor 전에 실행하는 것을 표준 순서로 둔다

### planner
- 입력: 후보 100개, 설정된 유형 비율
- 점수 = 검색량 × 개인 블로그 비율 ÷ 경쟁도, 주제 일관성 필터 통과 항목만
- 출력: `data/keywords/YYYY-WW.yaml` (5편, 각각 type/keyword/angle/status)

### writer
- 템플릿 4종 (`templates/*.md`): 코스형(course), 계절 큐레이션형(curation), 용품 리뷰형(gear), 디지털 노마드형(nomad)
- 코스 글 구조: 한줄요약 → 코스 표 → 이맘때 근거 → 구간별(실측·사진) → 지도 링크 → 오늘 챙긴 것(상품 1) → 하산 후 밥(표) → 주의사항
- 사진 슬롯: `[사진: 설명]` 형식으로 5개 이상 삽입
- 생성: `claude -p --model sonnet` 헤드리스 호출 (구독 계정, API 키 불필요). 시스템 프롬프트에 금지 사항 포함

### reviewer
- `rules.py`: 01 문서의 품질 원칙 9항목 중 자동 검사 가능한 8항목 (댓글 제외)
- `similarity.py`: 기존 발행 글과 유사도 (문장 단위 n-gram)
- `scorer.py`: `claude -p --model opus` 로 "사람이 쓴 것처럼 읽히는가, 경험이 구체적인가" 10점 채점, 7점 미만 재생성
- 제휴 고지문·외부 링크 수 검사

### publisher
- Playwright persistent context (`~/.tory-blogger/browser`) 로 로그인 세션 유지
- `https://blog.naver.com/<id>?Redirect=Write` 진입 → 제목 입력 → 본문 문단 단위 입력(복붙 아닌 타이핑, 문단 간 지연) → 태그 입력
- 사진 슬롯 위치에 안내 문구 삽입 후 **대기** → 사람이 발행 → URL 변경 감지
- 에디터 DOM이 바뀌면 셀렉터만 `selectors.yaml` 에서 수정

### distributor
- X API v2, Threads API로 요약 + 링크 게시
- 뉴스레터(스티비 또는 메일리) 주간 큐 파일에 적재
- 서치어드바이저는 API가 없어 등록 여부만 체크리스트로 안내

### analytics
- 네이버 블로그 통계는 API가 없음 → 사람이 주 1회 통계 페이지에서 내보내기 (CSV) → `data/reports/raw/`
- 애드포스트 리포트도 동일
- 스크립트가 CSV 파싱 → 주간 리포트 Markdown 생성 (KPI 표, 상위 글, 개선 제안은 Claude)

## 4. 설정 파일

- `config/pipeline.yaml`: 발행 요일, 유형 비율, 모델, 검수 임계값, 주제 키워드 목록
- `config/shopping_connect.yaml`: 상품 링크 허용 수, 위치, 고지문 문구
- `config/selectors.yaml`: 에디터 DOM 셀렉터
- `.env`: `NAVER_AD_CUSTOMER_ID`, `NAVER_AD_API_KEY`, `NAVER_AD_SECRET`, `NAVER_NCP_KEY_ID`, `NAVER_NCP_KEY`, `NAVER_BLOG_ID`

## 5. 스케줄 (launchd)

| 작업 | 시각 | 스크립트 |
|------|------|----------|
| 주간 계획 | 월 05:00 | `scripts/weekly_plan.py` |
| 초안 생성 | 화~토 05:00 | `scripts/daily_draft.py` |
| 주간 리포트 | 일 22:00 | `scripts/weekly_report.py` |

`fill_editor.py` 는 스케줄하지 않는다. 사람이 발행할 때 직접 실행한다.

## 6. 리스크와 대응

| 리스크 | 대응 |
|--------|------|
| 에디터 자동 입력이 봇으로 탐지 | 문단 단위 지연 입력, 하루 1편, 발행은 사람. 문제 시 클립보드 복사 모드로 전환 |
| 에디터 DOM 변경 | 셀렉터 외부 파일화, 실패 시 초안을 클립보드에 복사하고 종료 |
| AI 글 티 | 채점 임계값, 경험 문장 필수, 사람 검토 |
| 검색광고 API 한도 | 주 1회만 호출, 결과 캐시 |
